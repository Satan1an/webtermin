# APT repository

webtermin publishes a signed APT repository on GitHub Pages, so Debian,
Ubuntu, Armbian and Raspberry Pi OS hosts get new versions through
`apt upgrade` like any other package.

- URL: `https://satan1an.github.io/webtermin`
- Suite `stable`, component `main`, architectures `amd64` and `arm64`
- Contains the `.deb` files of the **5 newest releases** (pre-releases are
  excluded), so you can pin or downgrade to a recent version.

## Install (users)

```bash
sudo install -d -m 0755 /etc/apt/keyrings
curl -fsSL https://satan1an.github.io/webtermin/webtermin.gpg \
  | sudo tee /etc/apt/keyrings/webtermin.gpg >/dev/null

sudo tee /etc/apt/sources.list.d/webtermin.sources >/dev/null <<'EOF'
Types: deb
URIs: https://satan1an.github.io/webtermin
Suites: stable
Components: main
Signed-By: /etc/apt/keyrings/webtermin.gpg
EOF

sudo apt update
sudo apt install webtermin
```

The key is trusted only for this source (`Signed-By`), not system-wide.
Upgrades then arrive with `sudo apt update && sudo apt upgrade`. Your
`/etc/webtermin/config.yaml` is a conffile and is kept across upgrades.

Downgrade to an older version still in the repository:

```bash
apt list -a webtermin
sudo apt install webtermin=<version>
```

### Optional: automatic updates

If `unattended-upgrades` is installed, allow it to take webtermin updates too:

```bash
echo 'Unattended-Upgrade::Origins-Pattern { "origin=webtermin,codename=stable"; };' \
  | sudo tee /etc/apt/apt.conf.d/51webtermin-unattended
```

The service restarts after each upgrade, which drops open terminal sessions.
Leave this off if that matters to you.

## Maintainer setup (one time)

The repository is built by the `apt-repo` and `apt-pages` jobs in
`.github/workflows/release.yml` after GoReleaser publishes a release. Until the
signing key secret exists those jobs log a notice and skip; the release itself
is not affected.

The repository is deployed as a Pages artifact (`actions/deploy-pages`), not
committed to a `gh-pages` branch: it is rebuilt from the release assets each
time, so the releases stay the single source of truth and no `.deb` files pile
up in git history.

### 1. Signing key

Create a dedicated key that only signs the repository. Ed25519 is accepted by
current APT (Debian 13 verifies with Sequoia, which rejects SHA-1 and weak keys).

```bash
gpg --quick-gen-key "webtermin APT repository <work@anubis.ooo>" ed25519 sign never
gpg --list-secret-keys --keyid-format long     # note the fingerprint (FPR)
```

Store the private key in the repository secrets (`gh` reads the value from stdin):

```bash
gpg --armor --export-secret-keys FPR | gh secret set APT_GPG_PRIVATE_KEY --repo Satan1an/webtermin
# Only if you gave the key a passphrase:
gh secret set APT_GPG_PASSPHRASE --repo Satan1an/webtermin
```

Keep an offline backup of the key and a revocation certificate
(`gpg --gen-revoke FPR`). If the key is lost, every user has to download a new
`webtermin.gpg`.

### 2. GitHub Pages

1. **Settings → Pages → Build and deployment → Source: GitHub Actions.**
2. **Settings → Environments → `github-pages` → Deployment branches and tags:**
   add a tag rule `v*`. The environment GitHub creates allows only the default
   branch, and releases run on tags, so without this rule the deployment fails.

### 3. First publish

Publish the existing releases without cutting a new one:
**Actions → Release → Run workflow** (on `main`). This skips GoReleaser and only
rebuilds and deploys the APT repository. After that, every `v*` tag updates it
automatically.

Check from any machine:

```bash
curl -fsSL https://satan1an.github.io/webtermin/dists/stable/InRelease | head
```

## Layout

```
webtermin.gpg                      public key, binary (for /etc/apt/keyrings)
webtermin.asc                      same key, ASCII-armored
dists/stable/InRelease             signed inline
dists/stable/Release{,.gpg}        detached signature for older clients
dists/stable/main/binary-amd64/Packages{,.gz}
dists/stable/main/binary-arm64/Packages{,.gz}
pool/main/w/webtermin/*.deb
```

The repository is generated by `packaging/apt/build-repo.sh` with
`apt-ftparchive`. To build it locally:

```bash
packaging/apt/build-repo.sh <dir-with-debs> <out-dir> <key-fingerprint>
```

Change the number of releases kept with `KEEP_RELEASES` in the workflow.
